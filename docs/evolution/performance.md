# Native performance evidence

The deciding performance comparison is pending. The [acceptance budget](performance-budget.md) was fixed before deciding measurements. The [Rust measurement tool](../../proofs/performance/README.md) preserves raw results and completed-work counts.

The final tool measures Mesa Gallium's native `frametime` query. The installed Mesa `26.2.6` implementation computes the elapsed wall time since the preceding renderer frame, in milliseconds. It writes each value into a line-buffered file. The hidden query continues collecting without drawing an overlay. `GALLIUM_HUD_PERIOD=0` requests per-frame updates. The agent records boundary row counts after warmup and at completion, selecting consecutive real frame intervals. Mesa documents zero-period updates in its [environment variable reference](https://docs.mesa3d.org/envvars.html#gallium-hud-period), and the exact implementation was inspected in the [26.2.6 source archive](https://archive.mesa3d.org/mesa-26.2.6.tar.xz).

A rejected enabled pilot exposed a verifier capability conflict. HotSpot assigns breakpoint events to one JVMTI environment, so an independent breakpoint observer prevented the product from activating. Readiness refused that inactive runtime and the pilot failed. A native-binding alternative was also rejected after inspecting the game's Java-25 multi-release LWJGL implementation, which uses FFM. The final observer requests no breakpoint capability and performs no code or field transformation. The capability restriction is defined in [OpenJDK 25's capability allocator](https://raw.githubusercontent.com/openjdk/jdk/jdk-25%2B36/src/hotspot/share/prims/jvmtiManageCapabilities.cpp).

Startup ends at an observed usable native UI or world milestone. Menu mode requires visible native MainScreen and Options controls. World mode requires an alive native player in `IngameState`, an exact fixture account, zero LuaBuddy profile records, and the expected runtime-presence state. The native viewport, game version, role, and position are recorded. The deciding workload uses a fixed scene and records native state again at completion.

CPU time and resident memory come from the owned JVM's `/proc` records. Page size and clock tick frequency come from the actual host. Frame percentiles use linear interpolation between sorted observations. A VM-managed daemon thread reads existing native state and creates a fresh JNI local frame for each poll. It does not invoke mod logic. The reports retain initial and final renderer row counts, raw intervals, process samples, source artifact hashes, and screenshots. No Java method in the baseline is deoptimized by the measurement tool.

The non-deciding pilot ran Project Zomboid `42.22.2` and bundled Zulu Java `25.0.5+8-LTS` on Linux x86_64 with Mesa llvmpipe. It established that the measurement path reaches the actual unobstructed native menu and an ordinary player at the configured vanilla spawn. A four-second menu pilot captured 154 presentation intervals. A separate world-priming attempt captured 40 intervals during five seconds. Neither run is an acceptance comparison.

Early world-priming attempts were rejected because native cleanup did not complete. No deciding cache or performance pass was accepted from them. Those attempts exposed verifier input and cleanup assumptions. The tool now matches the exact fixture account before connecting and uses the native mouse-based click-to-start path. A later priming run completed the actual native pause-menu Quit and confirmation, exited with code zero, and copied its private fixture only afterward.

The observed host was busy, with load averages above the 24 available CPUs. The software-rendered world also consumed substantial process CPU and resident memory. A targeted thread profile was collected outside the deciding comparison. Final reporting must identify the limiting threads and separate variation from a repeatable loader cost. No speedup, regression, or budget pass is inferred from these pilot numbers.

Raw pilot evidence is retained outside Git in the LuaBuddy verification state directory under `2026-11-09-rust-performance-pilot` and `2026-11-09-rust-performance-world-prime`. The proprietary game and private fixture data are not release contents.
