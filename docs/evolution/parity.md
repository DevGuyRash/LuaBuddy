# Behavior ledger

The Rust migration starts from repository commit `84d495a`. The inventory at that commit contains 24 optional profile templates and 16 executable Lua hooks. A fresh installation must select none. Existing successful tests describe the old implementation until the corresponding Rust replacement is exercised.

The user later requested a complete purge with no historical compatibility. The current source therefore removes Java-agent migration, executable Lua-hook conversion, and the old `plugin` option. Generic unknown-option validation rejects that key. Native Rust hooks, extensions, update, repair, rollback, and recovery remain current behavior. Earlier migration assertions and artifact results below retain their historical scope.

The [runtime consumer](../../proofs/runtime/README.md) loads the actual production native library into the installed game JVM. Its expected results come from the requested behavior and the old externally observable contract. It uses isolated synthetic third-party mods as content and does not use foreign-language application helpers.

The native-runtime consumer was developed against Linux x86_64, Project Zomboid `42.22.2 3d39148846 integrity=pending`, and bundled Azul Java `25.0.5+8-LTS`. That is an observed test environment, not a platform-independent compatibility promise. Windows and macOS execution remain unverified.

Workshop subscription is distinct from installation, selection and runtime loading. The initial read-only scope was later expanded by the user's authorization for one agent-chosen subscription/download test. That item passed fresh delivery and the exercised client gameplay on the later candidate; see [Workshop evidence](workshop.md). Subscribe-only native activation remains an unresolved platform gate until the complete clean-install route is demonstrated.

The runtime consumer passed all 19 scenario groups against native artifact SHA256 `832d2d869d648a5bd304e03831df6eca4ce78543301efceabab962141ff0178c` and again through the aggregate on the later Steam-fix candidate `17ffaedb4f2d0a59002a536e408f53628d3a6d9d2b47f6b18a8b07951205c64a`. The consumer also passed all 19 groups through the exact `1d44f599` release override after the test-only portability correction. Formatting, strict Clippy, and a lockfile audit against the available advisory database also passed for the consumer. Selected actual reports and the command output were retained outside Git. This establishes the native-runtime scope above. The final aggregate verification must rerun the consumer after any later implementation change.

The consumer deliberately fails when cumulative failures disappear behind a successful refresh result, rejected new candidates lack failed status, rejected replacements alter loaded-generation diagnostics, unrelated new profiles are blocked by another candidate's preflight failure, or a dedicated server receives client runtime state. Graphical gameplay, each bundled profile's controls, multiplayer connection behavior, Workshop account operations, performance, and Windows/macOS execution remain separate delivery gates.

The native-only purge rechecked the current 19-group consumer on `1207d5d6`. The old hook-migration scenario is replaced with generic unsupported-configuration preflight, preserving a resident generation and callback through refusal and successful correction. Earlier migration results describe the older implementation only; migration is no longer a supported behavior.
